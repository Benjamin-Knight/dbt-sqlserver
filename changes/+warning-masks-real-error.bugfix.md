Stop reporting a SQL Server warning as the reason a model failed. When a warning and an error are both raised inside a nested batch - `EXEC()`, `sp_executesql` or a stored procedure - `pyodbc` and `mssql-python` can raise only the warning and discard the error; under `SET NOCOUNT ON` this happens every time. A common case is 8153, *Null value is eliminated by an aggregate*, from a `MAX`/`SUM` over NULLs. The error cannot be recovered and is not written to the SQL Server error log, so the adapter now says the real error was masked and how to find it: run the compiled SQL directly (SSMS shows every message), or capture it with an Extended Events session on `error_reported`. The warning text is still included.
